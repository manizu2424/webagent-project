# WEBAGENT.KR MVP 통합 문서 안내

이 디렉터리는 기존 기획 문서에서 반복되는 내용을 합치고, 성격이 다른 내용을 분리한 저장소의 공식 기준 문서다. 통합 전 원본은 중복과 충돌을 막기 위해 제거했으며 필요한 변경 이력은 버전 관리에서 확인한다.

## 문서 구성

1. [`01-MVP_통합_제품기획서.md`](./01-MVP_통합_제품기획서.md)
   - 브랜드, 타깃, 사용자 여정, 기능 범위, 화면 구성, KPI
   - 제품 요구사항의 단일 기준
2. [`02-데이터베이스_아키텍처_선택지.md`](./02-데이터베이스_아키텍처_선택지.md)
   - Supabase와 자체 PostgreSQL 비교
   - 기술 선택이 다시 필요할 때 참고하는 의사결정 문서
3. [`03-PostgreSQL_MVP_개발실행서.md`](./03-PostgreSQL_MVP_개발실행서.md)
   - 현재 채택된 자체 PostgreSQL 기준의 구현 계약, 보안, 단계별 완료 조건
   - 개발 작업의 실행 기준

## 현재 확정 사항

| 항목 | 결정 |
|---|---|
| 제품 | 중소기업용 무료 AI 업무 자동화 진단 및 상담 전환 서비스 |
| 웹 앱 | Next.js App Router + TypeScript |
| DB | WEBAGENT 전용 PostgreSQL |
| ORM | Drizzle ORM |
| 자동화·AI 호출 | n8n |
| 관리자 | 단일 관리자 로그인과 진단·상담 조회 |
| 배포 | Contabo VPS + Docker + Nginx Proxy Manager + Cloudflare |

## 중복 처리 원칙

- 제품 정의, 타깃, 기능 범위, 진단 폼, 결과 구성, 랜딩페이지, 사례, 일정, KPI는 `01`에 한 번만 둔다.
- Supabase와 자체 PostgreSQL의 비교는 구현 지침과 분리해 `02`에 둔다.
- API, 스키마, 상태, 보안, 배포, 테스트, Phase별 완료 조건은 `03`에 둔다.
- 제품 문서는 기술 구현을 지시하지 않고, 개발 실행서는 마케팅 문구를 중복 설명하지 않는다.
- 문서 간 충돌 시 `03`의 현재 기술 결정과 실제 코드·`README.md`를 우선한다.

## 유지관리 원칙

- 제품 요구사항은 `01`에서만 수정한다.
- DB 선택 근거와 대안 비교는 `02`에서만 수정한다.
- 현재 PostgreSQL 구현 계약과 완료 조건은 `03`에서만 수정한다.
- 개발 현황은 루트 `README.md`에서 관리하고, 문서와 실제 코드가 다르면 차이를 명시해 함께 갱신한다.
