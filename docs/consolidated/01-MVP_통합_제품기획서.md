# WEBAGENT.KR MVP 통합 제품기획서

## 1. 제품 정의

> 중소기업 사용자가 반복 업무를 입력하면 AI가 자동화 가능성을 분석하고, 맞춤 결과를 보여준 뒤 상담으로 연결하는 AI 자동화 영업 플랫폼

WEBAGENT.KR은 일반 홈페이지 제작사가 아니라 **중소기업을 위한 AI 자동화 구축 전문기업**으로 포지셔닝한다. 홈페이지는 문의 접수, 고객 관리, AI 분석과 업무 자동화를 연결하는 `Smart Website` 서비스로 취급한다.

- 브랜드: `WEBAGENT.KR`
- 핵심 슬로건: **AI로 일하는 회사를 만듭니다.**
- 보조 메시지: 홈페이지 제작부터 n8n 업무 자동화, AI Agent 구축까지 반복 업무를 줄이는 실전형 자동화 시스템을 구축합니다.

## 2. 목표와 검증 가설

핵심 목표는 방문자 수 자체가 아니라 아래 전환 흐름을 검증하는 것이다.

```text
사이트 방문 → 서비스 이해 → 무료 자동화 진단 → AI 분석 결과
→ 상담 신청 → 프로젝트 제안·계약
```

검증 가설은 다음과 같다.

> 중소기업 대표자와 실무자는 단순 문의 폼보다 자기 회사의 업무를 분석해 주는 무료 자동화 진단에 더 적극적으로 반응한다.

## 3. 타깃 고객

### 1차 고객

- 직원 5~50명 규모 중소기업
- 내부 개발자가 없는 회사
- Excel, 이메일, 문서 업무가 많은 회사
- 홈페이지 문의와 고객 정보를 수동으로 관리하는 회사
- 블로그·SNS 콘텐츠 제작 부담이 큰 회사
- AI 도입 의지는 있으나 시작점을 모르는 대표자와 실무자

### 초기 집중 업종

1. 건설·인테리어·부동산
2. 전문서비스업
3. 교육·학원·컨설팅
4. 제조·유통업
5. 1인 기업

초기 포트폴리오는 경험을 활용하기 쉬운 건설·전문서비스업 자동화 데모를 우선한다. 실제 고객 구축물이 아닌 경우 반드시 `자동화 데모` 또는 `샘플 구축 사례`로 표시한다.

## 4. MVP 범위

### P0: 출시 필수

- 반응형 랜딩페이지
- 5단계 무료 AI 자동화 진단 폼
- 고객·진단 원본 DB 저장
- n8n Webhook과 AI 분석
- 구조화된 분석 결과 저장·조회
- 처리 중·완료·실패 상태를 갖는 결과 페이지
- Telegram 또는 이메일 관리자 알림
- 상담 신청과 DB 저장
- 개인정보 수집 동의 및 개인정보처리방침
- 관리자 로그인, 진단·상담 목록 및 상세 조회
- Docker 기반 운영 배포와 DB 백업

### P1: 출시 직후

- 고객 결과 이메일
- 자동화 사례 상세
- MDX 블로그 글 3개
- GA4·Microsoft Clarity
- SEO 메타데이터, sitemap, Open Graph

### P2: 검증 후

- PDF 진단 보고서와 공유 링크
- 상담 일정 예약
- 고객 계정·포털
- 결제와 프로젝트 관리
- 견적서·계약서 자동 생성
- 자동화 실행 로그 대시보드
- 사내 문서 RAG, 실시간 채팅, 다국어, 모바일 앱

## 5. 정보구조와 랜딩페이지

```text
홈
├─ 무료 자동화 진단
├─ 자동화 사례
│  ├─ 문의 자동화
│  ├─ 견적 자동화
│  └─ 콘텐츠 자동화
├─ 블로그
├─ 회사소개
├─ 상담신청
└─ 개인정보처리방침
```

홈 화면은 `Hero → 문제 제시 → Before/After → 서비스 → 사례 → 진단 CTA → 구축 절차 → 신뢰 요소 → FAQ → 최종 CTA` 순서로 구성한다.

Hero의 주 메시지는 `AI로 일하는 회사를 만듭니다.`로 통일한다. 과도한 AI 로봇 이미지를 쓰는 대신 `문의 → AI 분류 → DB 저장 → 담당자 알림 → 답변 초안`처럼 실제 업무 흐름을 보여준다.

서비스 카드는 MVP에서 상세 페이지 없이 다음 5개를 노출한다.

- AI Automation
- n8n Automation
- Smart Website
- AI Agent
- AI Consulting

## 6. 핵심 사용자 여정

1. 방문자가 반복 업무 문제와 자동화 전후 사례를 확인한다.
2. 무료 진단을 시작하고 회사·업무·연락 정보를 단계별로 입력한다.
3. 제출 직후 공개 식별자가 포함된 결과 페이지로 이동한다.
4. 분석 중에는 처리 상태를 안내하고, 완료되면 구조화된 결과를 표시한다.
5. 결과 하단에서 상담 신청, 결과 이메일 수신, 다시 진단하기를 선택한다.
6. 관리자는 신규 진단 알림을 받고 관리자 화면에서 후속 상태를 관리한다.

## 7. 진단 입력 항목

| 단계 | 내용 |
|---|---|
| 1. 회사 정보 | 회사명, 업종, 직원 수, 홈페이지 유무 |
| 2. 사용 도구 | Excel, Google Sheets, 이메일, 카카오톡, ERP, CRM, WordPress, 네이버, Slack, Telegram, 기타 |
| 3. 반복 업무 | 문의, 견적, 고객정보, 이메일, 보고서, 블로그, SNS, 문서 정리, 상담 기록, 내부 알림 |
| 4. 업무량·문제 | 하루 반복 시간, 담당 인원, 월 처리량, 가장 불편한 업무, 현재 처리 방식 |
| 5. 상담 정보 | 도입 목적, 예산 범위, 상담 방식, 이름, 이메일, 전화번호, 개인정보 동의 |

한 화면에 모든 문항을 노출하지 않는다. 각 단계에는 진행률, 이전·다음 버튼, 명확한 오류 메시지를 제공하고 최종 제출은 한 번만 실행한다.

## 8. AI 결과 구성

결과는 장문 답변이 아니라 다음 필드를 갖는 구조화 데이터로 생성한다.

- 자동화 준비도: 0~100점
- 우선 추천 업무와 추천 이유
- 업무별 난이도
- 업무별·전체 월 예상 절감 시간
- 추천 시스템 구성
- 권장 구축 단계
- 짧은 종합 요약

예상 효과는 보장값처럼 표현하지 않고 입력값을 바탕으로 한 추정치임을 안내한다. 세부 설계 전체를 무료 결과에 공개하기보다 우선순위와 기대 효과를 명확히 보여주고 상담으로 연결한다.

## 9. 대표 자동화 데모

### 문의 자동화

`문의 제출 → AI 유형 분류 → DB 저장 → 담당자 알림 → 접수 이메일 → 답변 초안`

효과: 문의 누락 방지, 응답 속도 개선, 고객 데이터 축적.

### 견적 자동화

`견적 요청 → 요구사항 분석 → 추가 질문 → 견적 초안 → 관리자 검토`

효과: 작성 시간 단축, 상담 기준 표준화, 영업 대응 개선.

### 콘텐츠 자동화

`키워드 → 자료 수집 → AI 초안 → 이미지 준비 → WordPress 임시글 → 사람 검수`

완전 자동 발행 대신 사람의 최종 검수를 포함한 반자동 방식으로 소개한다.

## 10. 관리자 운영

관리자 화면은 초기 CRM 수준으로 확장하지 않는다. 대시보드 숫자 카드, 진단 목록·상세, 상담 목록, 메모와 상태 변경만 제공한다.

- 진단 상태: `SUBMITTED`, `PROCESSING`, `COMPLETED`, `FAILED`
- 상담 영업 상태: `NEW`, `CONTACT_PENDING`, `SCHEDULED`, `PROPOSAL_SENT`, `CONTRACTED`, `ON_HOLD`, `CLOSED`

## 11. 성공 기준과 KPI

한 명의 실제 사용자가 진단 제출부터 AI 결과 확인, 상담 신청까지 완료하고 관리자가 이를 확인할 수 있으면 핵심 흐름이 완성된 것이다.

| 지표 | 초기 목표 |
|---|---:|
| 방문자 대비 진단 시작률 | 8% 이상 |
| 진단 시작 대비 완료율 | 50% 이상 |
| 진단 완료 대비 상담 신청률 | 15% 이상 |
| 상담 대비 유료 제안 전환율 | 30% 이상 |

초기에는 트래픽보다 진단 완료 수, 상담 수, 계약 전환을 우선해 본다.

## 13. 제품 리스크와 대응

- 결과가 일반적임: 업종·규모·사용 도구·업무량을 함께 분석하고 구조화된 출력을 강제한다.
- 폼이 김: 5단계로 나누고 필요한 질문만 수집한다.
- 결과 후 이탈: 결과 바로 아래에 구체적인 상담 CTA를 둔다.
- 사례 부족: 실제 고객 사례처럼 오인되지 않도록 데모임을 명시한다.
- 서비스가 넓어 보임: 첫 화면은 `AI 업무 자동화` 하나에 집중하고 기술명은 구현 수단으로 배치한다.
